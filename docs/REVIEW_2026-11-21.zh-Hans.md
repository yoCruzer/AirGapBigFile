# AirGap BigFile 架构、完整性与传输效率审查

审查时间为北京时间 2026-11-20 至 21 日。开始时工作树干净，`git ls-remote --exit-code origin refs/heads/main` 返回 `5ac634deeddd95fdf0bc8390efb4284ef85d0299`，与本地 HEAD 一致。以下修复均在该基线上验证。

本次优先修复了两个会影响传输结果的问题。旧发送端在编码器返回失败或实际没有绘制图像时仍可能累计进度。文件准备结束后再次读取同一分块时，旧实现也只检查长度。两处都已增加发送前或计数前的明确校验。可压缩文件的提前换块作为实验选项提供，默认沿用完整帧组。

## 审查范围与架构判断

| 路径 | 结论与边界 |
| --- | --- |
| 文件选择、拖放、准备 | 检查文件名、大小、5/10 MiB 边界、120 块上限、短读、取消和同一文件重选。跨块整文件哈希按文件顺序增量更新，准备后的状态只保存文件引用和元数据。浏览器、Web Crypto 和 WASM 的内部缓冲会增加进程内存。 |
| 协议和身份 | manifest + 分块最多使用 121 个不同的 7 位 wire ID。不同发送会话可以碰到相同 ID。接收端需要结合预期 ID、大小和 SHA-256 识别分块，按索引重建并核对整文件。SHA-256 提供内容一致性，v1 没有提供发送者认证或内容加密。 |
| 调度与并发 | 纯调度器负责清单、轮播和定向顺序，异步生命周期负责单元所有权。暂停保留已选单元，继续复用初始化结果，停止和切换模式使旧结果失效。保留这个划分，并把与 WASM 版本相关的喂数逻辑抽到单独模块。 |
| 浏览器与私有数据 | 应用用 textContent 显示用户文件名，只在 localStorage 保存语言偏好。审查覆盖可见性暂停、唤醒锁异步释放、异常停止、旧画布显隐、语言切换以及两种入口的 CSP。产品没有反向确认通道。 |
| 打包与交付 | 核对源码装配顺序、确定性、三个运行时依赖的摘要、发布工作流权限和 Pages 上传目录。Pages 上传单个已验证的 HTML。仓库中供参考的上游接收器页面和服务工作线程不进入发送端产物。 |
| 重建和持久化 | 本仓库实现浏览器发送端。用固定版 WASM 解码器做数字回放，并以独立文件字节为真值。原生 AirGapFree 的数据库迁移、跨启动去重、删除恢复、最终落盘和相机链路需要在接收端工程独立验收。 |

## 修复清单

优先级按影响和可达路径划分。P1 涉及错误数据、错误进度或无法运行。P2 涉及安全加固、吞吐或兼容性。P3 涉及边界行为和诊断。

| 优先级 | 审查发现及影响 | 已实施的改动与验证 |
| --- | --- | --- |
| P1 | `src/app.js` 忽略 configure、encode、render、next_frame 的部分返回值。新流没有待画帧时，首次 render 可返回 0。短块已结束编码，再次 flush 也会产生错误返回。 | `src/encoder.js` 按 v0.6.4 ABI 检查缓冲大小、分配、初始化、每次写入和结束状态。每次写入取当前 WASM 堆视图。只在整块边界补零长度调用。先生成再绘制，成功后才计数。配置失败禁用启动，运行失败停发并释放唤醒锁。用真实 WASM、模拟分配失败、堆变化、不同块长和显示失败分别覆盖。 |
| P1 | 准备后的分块重新读取时只校验字节数。如果底层读回了长度相同的不同内容，发送端会持续展示无法匹配清单的数据。 | 每次向编码器交付分块前验证范围、长度和 SHA-256。正常读、等长变化、短读、越界、重新选择同一文件均有测试。运行集成测试确认变化的数据没有初始化为新的编码单元。 |
| P1 | 文档要求 Python 3，系统 Python 3.9.6 实际执行构建时报 `write_text(..., newline=...)` 参数错误。原构建还共用固定临时文件名。 | 构建按 UTF-8 字节写入同目录独立临时文件，再原子替换。系统 Python 完成重建、重复构建和产物验证。 |
| P2 | 离线发行文件继承开发页的同源连接权限，并允许任意 inline、data 和 blob 脚本。原有校验只单独锁定 WASM，不能发现重建前第三方 JS 已变化。 | 发布物默认拒绝资源加载与网络连接，仅放行构建生成的精确脚本哈希及 WASM 编译。开发页按同源方式加载脚本和 WASM。校验器独立重算 CSP 哈希，固定哈希库、胶水 JS 和 WASM 摘要。JS 胶水还与仓库内原始发布压缩包对应条目比对。五个隔离负例均被拒绝。 |
| P2 | CI 和 Pages 的直接 Action 使用可移动主版本标签。CI checkout 默认在后续步骤保留凭据。 | 按上游已解析的提交锁定当前直接依赖，并关闭 CI checkout 的凭据保留。远端工作流执行仍是发布前验证项。 |
| P2 | 按原始字节数计算帧数会让可压缩分块在喷泉序列已经重新开始后继续占用屏幕，后续分块需要等待。 | 新增默认关闭的「缩短重复的喷泉编码轮次」。只在分块已经展示且固定版编码器报告序号回到 1 后缩短，至少展示 30 帧。清单和完整预算模式仍可用。运行时测试覆盖开关、无回绕和下限，真实 WASM 覆盖可压缩及稠密输入。开启时预计轮播时长仍按完整预算计算。 |
| P2 | 准备阶段用 JavaScript 对各块重复哈希，单块文件甚至将相同内容完整计算两次。 | 单块复用摘要，多块保留增量整文件哈希，块摘要优先 Web Crypto。缺少 SubtleCrypto 时走原本地实现。两条路径与 Node 独立哈希比对。 |
| P2 | 晚到的末帧按计划时刻判断停留时间，实际显示可能偏短。重新开始时也可能在首帧就绪前显示上次留下的画布。 | 从成功提交时刻计算末帧停留，切换单元时避免额外消耗一次发送时隙，新会话和显式切换模式等到成功提交才显示画布。覆盖晚帧、暂停、后台、继续和按帧切换。 |
| P3 | 校验器隐式转换哈希类型，数组遍历会跳过稀疏槽位，UTF-16 孤立代理项无法无损编码。逻辑 ID 函数对极大合法整数偏移存在加法精度问题。 | 严格校验摘要字符串、逐项检查索引，拒绝孤立代理项，保留合法补充平面字符，取低位后再相加。覆盖异常元数据、边界偏移和全部 128 种基址余数下的 121 个单元。 |
| P3 | 一个单元在进入加载微任务前已经失效时，旧实现仍会发起读操作。同一文件在取消或失败后重选，也可能不产生文件选择变化事件。 | 读取前再次确认所有权，文件选择后清空输入控件值，保留会话自己持有的 File。已开始的浏览器范围读或摘要运算可能完成，失效结果不能初始化编码器。 |

固定版本的 C 接口实现规定了短块结束、渲染结果和喷泉序号重置的语义。升级 WASM 时需要重新核对这些假设。查询 GitHub 公告时，指定版本的 npm 哈希库查询及 libcimbar 仓库公开公告查询均返回空列表。此次没有对 WASM 内全部间接原生库做源码级审计。[编码接口实现](https://github.com/sz3/libcimbar/blob/v0.6.4/src/lib/cimbar_js/cimbar_js.cpp) · [解码接口实现](https://github.com/sz3/libcimbar/blob/v0.6.4/src/lib/cimbar_js/cimbar_recv_js.cpp)

## 实测结果

环境为同一台 macOS 27.0.1 arm64 开发机，Node 24.21.0、npm 11.19.0、Python 3.9.6、系统 WebKit（本机 Safari 27.0.1）、Swift 6.4.2。所有输入来自仓库黄金样本或内存生成的数据。

### 数字传输回放

最终 standalone 以 file:// 在非持久 WebKit 窗口打开。通过正常文件选择、准备、开始和停止入口，读取真实 WebGL 画布，使用固定的 1.25 倍缩放、0.75 px 模糊和边缘留白模拟采样，再调用上游解码器。两个分块分别验证大小和 SHA-256，重建后逐字节对比输入。合成输入为 5,244,114 字节，字节模式为索引模 251，整文件 SHA-256 为 `a488ad775d9305e156c6f482310f8b5d0c6cbb5ef9af2aafc74706da872d3d23`。

| 最终产物，30 FPS / 2× | 清单累计展示 | 第一分块展示 | 第二分块展示至解码 | 开始到取齐全部解码数据 | 校验 |
| --- | ---: | ---: | ---: | ---: | --- |
| 完整轮次 | 60 帧 | 1,399 帧 | 1 帧 | 48.825 秒 | 通过 |
| 缩短重复轮次 | 60 帧 | 95 帧 | 1 帧 | 5.350 秒 | 通过 |

两行是同一产物各一次配对回放。时间包含发送、同步画布采样、解码与轮询，排除准备及取齐后的断言。第二块首帧已经可以重建时测试即停止，发送端本身仍按帧组规则运行。这个样本的主要收益来自第二块更早开始。两次离线运行的资源加载记录均为空。另一次 5.310 秒的实验组选用实际解码得到的 7 位 wire ID 定位清单与分块，核对分块摘要和逐字节重建同样通过。

首次探索采用原尺寸直接采样，在黑色及白色留白下分别出现约 20 秒内只识别到第一分块的情况。调整数字采样条件后，完整轮次和提前换块都成功。实际相机的对焦、曝光、掉帧和拍摄角度可能改变结果。已压缩或难压缩的文件可能没有提前换块收益。固定 WASM 对 5 MiB 稠密伪随机输入的前 31 帧均未回绕。

开发入口另用一次仅绑定 127.0.0.1 的静态服务验证。相同样本在实验设置下用时 5.347 秒，重建和哈希一致。浏览器只加载了 14 个本地脚本或 WASM 子资源。

## 后续优先级

1. **P1，发布前验证。** 在有屏幕与相机的配对设备上分别用可压缩和已压缩输入测试。比较完整轮次与提前换块的首次整文件验证时间、缺块数、定向重传次数和失败率，记录每组的重复次数和接收端哈希。提交候选版本后执行远端 CI。具体记录字段见[真机矩阵](SENDER_V1_1_DEVICE_TEST.md)。
2. **P2，主线程响应。** 对慢设备的 10 MiB 分块采集整文件增量哈希及 WASM 初始化的长任务时长。若取消响应或换块间隙成为实测瓶颈，再评估 Worker 和有界预读，同时测峰值内存、停止后的过期读及收益。
3. **P3，链路调参。** 在接收端积累识别率和有效 KiB/s 后比较 FPS、冗余度和清单间隔。清单承担中途加入与重传定位，减少清单需要同时验证晚加入和漏扫场景。当前稳定默认值为 15 FPS / 2×。
